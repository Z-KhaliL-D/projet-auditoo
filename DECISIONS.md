# Decisions

- 2026-10-07: Run web and api together with `concurrently` (dev-only dependency). Reason: portable and gives labeled output, unlike shell `&`.
- 2026-10-07: Keep the shadcn `base-nova` style. Reason: the generated default is fine for now.
- 2026-10-07: Ops use an envelope (`opId`, `createdAt`, `type`) with a nested `payload`. Reason: keeps metadata separate from entity fields.
- 2026-10-07: Sort ranks with plain `<` in `compareByRank`, never `localeCompare`. Reason: `fractional-indexing` ranks are ordered by character code.
- 2026-10-07: `cursorSchema` is a non-negative integer used for the pull cursor. Reason: the cursor is a server sequence counter, not a timestamp.
- 2026-10-07: The pull cursor is one global server counter (`meta.seq`). Every row write stores the new value in the row's `seq`. Reason: one number matches `cursorSchema` and `rowid` does not change on update.
- 2026-10-07: Deletes win over edits: rename, move or delete on a missing or deleted target is a no-op reported as applied. Reason: the client can clear its outbox and the delete is never undone by a stale edit.
- 2026-10-07: New data wins over deletes: `space.create` under a deleted level restores the level (deletedAt = null, seq bumped) and its old spaces stay deleted. Reason: new data entered on site must never be lost.
- 2026-10-07: `updatedAt` is the server clock at apply time, and conflicts resolve by arrival order. Reason: phone clocks drift.
- 2026-10-07: The server cascades `level.delete` to the level's live spaces. Reason: a space created on another device would otherwise stay alive under a deleted level.
- 2026-10-07: An invalid push body returns 400 and applies nothing, and a DB error rolls back the whole batch. The client must handle a 400 (drop or quarantine the offending op) so one bad op can never block the outbox forever. Reason: all-or-nothing batches avoid silent partial data loss.
- 2026-10-07: Pull has no size limit for now. Reason: inspection data is small and paging would change `PullResponse`.
- 2026-10-07: Mutation functions take the Dexie `db` as first argument, with one exported `db` instance for the app. Reason: explicit and easy to test with fake-indexeddb.
- 2026-10-07: The outbox uses an auto-increment local key with the whole `Op` stored and `opId` indexed. Reason: send order equals mutation order without depending on device clocks.
- 2026-10-07: Mutations take a target index and compute the rank inside the transaction from the live siblings. Reason: a stale UI list can never produce a wrong rank.
- 2026-10-07: Deleting a level locally soft-deletes its spaces and appends a single `level.delete` op. Reason: the server cascades, so extra ops would only flood the outbox.
- 2026-10-07: Edits on a missing or deleted target are silent no-ops with nothing appended. Names are validated with `nameSchema` and every op is parsed with `opSchema` before it enters the outbox. Reason: bad ops never reach the server, so its 400 stays a safety net.
- 2026-10-10: Undo for deletes uses new `level.restore` and `space.restore` ops. Reason: undo stays a normal synced op and keeps identity, unlike delaying the delete or recreating items.
- 2026-10-10: Restoring a level revives only the spaces its own delete cascaded to (same `deletedAt`). Reason: spaces deleted earlier must stay deleted.
- 2026-10-10: Timestamps are strictly increasing on the server (`meta.ts`) and in the client (`tick`). Reason: the cascade match on `deletedAt` breaks if two ops share a timestamp, for example in one push batch.
- 2026-10-10: Restoring a space under a deleted level is an applied no-op. Reason: undo is not new data, and the space would be invisible.
- 2026-10-10: Main screen is one page with collapsible level sections, expanded by default. Reason: one scroll gives an overview of the building.
- 2026-10-10: Add flow is inline: an "Add space" row at the end of each level that keeps the input open after Enter, and a fixed bottom "Add level" button. Reason: one tap plus typing, and the main action is in thumb reach.
- 2026-10-10: Row actions are a 44px menu button (Rename, Delete) with in-place rename. Reason: keeps the row body free for swipe-to-delete later. Empty slots are reserved for the drag handle and the header sync badge, with no fake placeholders.
- 2026-10-10: Undo toasts use `sonner`, and the UI adds `dexie-react-hooks`. Reason: sonner is the shadcn toast, and `useLiveQuery` needs the hooks package.
- 2026-10-10: Teal accent, dark mode follows the system with no toggle. Reason: calm, readable in both themes, and less header clutter.
- 2026-10-10: A few component tests cover add, rename, delete and undo, using Testing Library and jsdom (dev-only). Reason: guards the core flows without testing styling.
- 2026-10-10: The generated shadcn `sonner` wrapper no longer uses `next-themes`; it passes `theme="system"`. Reason: dark mode already follows the system through the `.dark` class, so the extra dependency is unnecessary.
- 2026-10-11: A 400 on a push batch is isolated by resending ops one at a time. Refused ops move to a `rejected` table (Dexie schema v2) and are never deleted; any rejected op puts the badge in the error state. Reason: one bad op must not block the outbox, and data must never be lost.
- 2026-10-11: A pull skips rows with pending outbox ops, including the spaces of a level with a pending delete or restore, copies every other row exactly, and advances the cursor only when nothing was skipped. Reason: a skipped row whose op was a no-op on the server would otherwise never be delivered.
- 2026-10-11: Rejected ops do not protect their entities from a pull; the server state wins. Reason: protecting them would stall the cursor forever and re-download everything since it.
- 2026-10-11: The engine syncs on start, on `online`, window focus and visibility, and 1 second after the outbox grows. Triggers bypass the retry delay, and retries back off from 2s to 60s with jitter. Reason: user and network signals deserve an immediate attempt, failures should not hammer the server.
- 2026-10-11: Requests time out after 15 seconds, and a thrown fetch, a timeout or a non-JSON 200 all count as offline. Reason: a hanging fetch would block every later sync, and captive portals answer 200 with HTML.
- 2026-10-11: One sync runs at a time per tab; a trigger during a run asks for one more pass. Multiple tabs rely on opId idempotency, with no Web Locks. Reason: simpler, and duplicate work is harmless.
- 2026-10-11: The engine is a module singleton started in `main.tsx`, read through `useSyncExternalStore`, with pending and rejected counts from `useLiveQuery`. Reason: no new library, and no double mount under StrictMode.
- 2026-10-11: The header badge is tappable and runs a sync now. Reason: a 44px recovery action for stuck states.
- 2026-10-11: Sync tests use a fake transport for engine logic plus an integration test with two simulated devices on the real API app. Reason: the flagged cases depend on exact server behavior.
- 2026-10-11: The engine polls about every 30 seconds with 20 percent jitter. Each successful cycle schedules the next one in the single timer slot, failures use the backoff instead, and nothing is scheduled while the page is hidden. Reason: an idle online device would otherwise never see other devices' changes, and one timer slot prevents overlap and hammering a failing server.
- 2026-10-12: Drag and drop uses the stable `@dnd-kit/core`, `@dnd-kit/sortable` and `@dnd-kit/utilities`, not the 0.x `@dnd-kit/react`. Reason: stable API and a documented pattern for lists inside lists.
- 2026-10-12: A drag starts instantly from a 44px handle with `touch-action: none`, after 4px of movement, and a keyboard sensor is also active. The row body carries no drag listeners. Reason: responsive and reliable on iOS and Android, scrolling works everywhere except the handle, and swipe-to-delete keeps the row body.
- 2026-10-12: One `DndContext` for the whole screen: spaces are sortable inside each level, and levels and cross-level moves extend the same context. Delivered in slices: 7a spaces inside a level, 7b levels, 7c a space into another level. Reason: building the structure once avoids reworking it for each slice.
- 2026-10-12: Dragging uses a `DragOverlay` copy, with the source row dimmed in place. Reason: a floating copy stays smooth across containers and while scrolling.
- 2026-10-12: After a drop the dropped order is shown until Dexie's live query reflects it (or 500 ms after the write finishes if it changed nothing). Reason: avoids the row snapping back for a frame.
- 2026-10-12: A drop resolves to the final index among the destination's live siblings and calls the existing move mutations. A drop that changes nothing writes no op. Reason: matches the mutations' index semantics and keeps no-op moves out of the outbox.
- 2026-10-12: Drag handles are always visible, with no reorder mode. Reason: fastest to use, and the left slot was reserved for them.
- 2026-10-12: Drag logic is unit-tested as pure functions and a hook, with handle rendering checked in a component test. The feel is verified by hand on a phone, and Playwright is deferred. Reason: jsdom cannot simulate real pointer drags or layout.
- 2026-10-12: Levels and spaces share one `DndContext`, and collision detection only compares items of the same kind. Reason: otherwise a dragged level could land on one of its own spaces.
- 2026-10-12: While a level is dragged, every level folds visually without touching the saved collapsed state. Reason: expanded levels are too tall to carry on a phone.
- 2026-10-12: A space is dropped on another level through a live preview: when it hovers another level it appears there at once (above or below the hovered space, or at the end of an empty or folded level), and the drop writes that position. Reason: the other rows shift to show the gap, and the sortable list needs no cross-list special cases.
- 2026-10-12: Only a level with no visible spaces (empty or folded) is a drop target for a space; otherwise the nearest space decides. A folded level is not expanded by hovering and gets a primary ring as the drop cue. Reason: a level that shows spaces already has rows to drop onto, and expanding on hover would shift the layout under the finger.
- 2026-10-12: The final move is measured against the stored position, so dragging out of a level and back writes no op. Reason: previews are not data and must not leave junk ops in the outbox.
- 2026-10-13: Dragging keeps the layout stable instead of relying on one measurement at drag start. Droppables are re-measured throughout the drag, a space that leaves its level keeps an empty row of the same height in the old position (a ghost), and when levels fold or unfold the page keeps its length with temporary bottom padding and scrolls so the carried level stays where it was on screen. Reason: the rows at and above the finger no longer move during a drag, so the gap cannot land a row off.
- 2026-10-13: The drag overlay has no drop animation. Reason: it aims at a position measured before the layout settles, so the item would fly to a spot it then leaves.
- 2026-10-13: Swipe-to-delete is custom pointer-event code on the row body with `touch-action: pan-y`, not a library. Reason: vertical scrolling stays with the browser, there is no new dependency, and it stays independent of dnd-kit.
- 2026-10-13: Only the name area starts a swipe; the drag handle and the menu button are outside it, and the sliding applies to an inner element because dnd-kit owns the row's own transform. Swipes are off while renaming and while any drag is active. Reason: each control keeps its own gesture.
- 2026-10-13: A left swipe past 40 percent of the row width, or a fast flick of at least 15 percent, deletes a space at once with the existing undo toast. A level needs 60 percent and has no flick shortcut. Reason: deletes are immediate with undo, and a level takes its spaces with it.
- 2026-10-13: Ambiguous moves go to scrolling: only a clearly horizontal leftward move (10px, 1.5 times more horizontal than vertical) starts a swipe, and a browser cancel resets the row. Reason: swiping must never block scrolling.
- 2026-10-13: A level swipe moves only the header, and the section is removed when it commits. The click that follows a swipe is suppressed. A committed row slides off for 150 ms before the delete runs, with no slide for reduced motion. Reason: visual feedback without delaying the data change noticeably.
- 2026-10-13: No discoverability hint for swiping; the row menu still has Delete. Reason: keyboard and screen-reader users keep a full path, and a hint can come later.
- 2026-10-11: The PWA uses `@serwist/vite` with a hand-written `src/sw.ts`, plus `serwist` and `@serwist/window`. It precaches every emitted file, falls back to the cached `index.html` for navigations, and has no other runtime caching. It builds on Vite 8. Reason: the whole shell opens with no network, even after a reload.
- 2026-10-11: `/api` is never cached, at four layers: an explicit network-only service worker route for every method, `Cache-Control: no-store` on every API response, `cache: "no-store"` on every sync request, and no runtime caching rule that could match it. Reason: a cached push answer would make the client delete outbox ops the server never received.
- 2026-10-11: A new version waits instead of taking over. A persistent toast ("A new version is available", Reload) lets the inspector choose when to switch; if ignored, it applies at the next cold start. Once it takes over, every open tab reloads. The app checks for updates on start and when the page becomes visible, at most every 15 minutes. Reason: taking over immediately would give an open page new files for old hashed chunks, and could collide with a Dexie schema upgrade.
- 2026-10-11: API and shared schema changes stay backward compatible with the previous client version. Reason: an inspector can open an old version after days offline and push ops from it; a rejected op is quarantined. A client-version header can wait until a breaking change forces it.
- 2026-10-11: The Cyrillic and Vietnamese font subsets are not precached; Latin and Latin-extended are. Reason: smaller download, and EU accented names stay covered.
- 2026-10-11: The manifest uses `display: standalone` (not `fullscreen`), white theme and background colors, free orientation, and light and dark `theme-color` meta tags. Reason: inspectors need the status bar for the clock and battery, and iOS only supports standalone.
- 2026-10-11: Icons are a placeholder (stacked bars on teal) drawn as SVG and rendered to PNG with a throwaway script. Reason: the project has no branding yet.
- 2026-10-11: iOS Safari shows a small dismissible banner (Share, then Add to Home Screen) when the app is not installed, and stays hidden for 3 days after a dismissal. Persistent storage is requested at startup. There is no custom install button. Reason: Safari erases a site's IndexedDB after about a week without use unless it is installed, which would lose unsynced work.
- 2026-10-11: The service worker is registered only in production builds, after the page loads, and is off in dev. It is tested with `vite build` and a real browser. Reason: a cached shell in dev would hide changes.
